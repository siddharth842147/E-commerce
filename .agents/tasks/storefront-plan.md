## Codebase findings (read before coding)

### Critical Next.js 16 gotchas
- `params` and `searchParams` are **Promises** — always `await` them in both page and layout components.
- Use `PageProps<'/route/[param]'>` and `LayoutProps<'/route'>` global helpers (generated by `next dev`/`next build`) — no import needed.

### Button / shadcn pattern
- `components/ui/button.tsx` imports from `@base-ui/react/button`, NOT standard HTML. All shadcn components installed via `npx shadcn@latest add` follow the same pattern. Do **not** rewrite them.
- `cn()` is imported from the `'cn'` package directly in button.tsx (not `@/lib/utils`). Follow the same import in any new ui/ files.

### Server actions
- All actions return `ApiResponse<T>` from `@/lib/api-response`: `{success:true,data:T}` or `{success:false,error:string}`.
- No react-hook-form — forms use `FormData` + server actions (see `lib/auth-actions.ts`).

### Tailwind v4
- CSS uses `@import "tailwindcss"` (no `@tailwind base/components/utilities`).
- Theme variables defined in `globals.css` `@theme inline {}` block — use CSS variables like `var(--primary)` or Tailwind classes like `bg-primary`.

### Route groups & middleware
- Middleware protects `/account/*` and `/admin/*`.
- Dashboard pages go under `app/(dashboard)/account/...` → resolves to `/account/profile`, `/account/orders`, etc.
- Auth pages go under `app/(auth)/login/...` → resolves to `/login`, `/register`, etc.

### Existing actions
- `getCart()`, `addToCart()`, `updateCartItemQuantity()`, `removeFromCart()` — `actions/cart.ts`
- `placeCodOrder()`, `enrichCartWithTaxRates()` — `actions/checkout.ts`
- `getProducts()`, `getProductDetail()` — `actions/products.ts`
- `getCategories()` — `actions/categories.ts`
- `getNotificationPreferences()`, `updateNotificationPreferences()` — `actions/notifications.ts`
- `signInWithEmail()`, `signUpWithEmail()`, `sendPhoneOtp()`, `verifyPhoneOtp()`, `resetPassword()`, `updatePassword()`, `signOut()` — `lib/auth-actions.ts`
- `initiateRazorpayCheckout()`, `placeCodOrderAction()` — `lib/checkout-client.ts`

### Invoice PDF
- `lib/invoice/generate-invoice.ts` exists — exports `generateInvoicePDF(props: InvoicePDFProps): Promise<Buffer>`
- `lib/invoice/InvoicePDF.tsx` — full PDF layout already built

## Edge Cases & Gotchas

1. **`cn` import**: `components/ui/button.tsx` imports from `'cn'` (the package), not `@/lib/utils`. Match this in any new component that lives in `components/ui/`. Components in `components/shared/` should import from `@/lib/utils`.

2. **No react-hook-form**: It's not installed. All forms use native `FormData` with `<form action={serverAction}>` or `useState`+fetch patterns. The checkout page uses `useState` since it's a multi-step client component.

3. **Sonner not installed**: Must `npm install sonner` before importing `Toaster` from `sonner` in layout.tsx.

4. **ProductWithVariants type**: Exported from `@/services/product.service` (not from types/db.ts). Import as `import type { ProductWithVariants } from '@/services/product.service'`.

5. **Order shippingAddress is JSONB**: `order.shippingAddress` is typed as `unknown` from Drizzle. Cast it: `order.shippingAddress as ShippingAddress` (type from `@/types/checkout`).

6. **Cart merge on login**: The existing codebase discards (not merges) the guest cart on login via `discardGuestCartOnLogin()`. The login page must call this action after successful login before redirecting.

7. **`@/lib/utils` vs `'cn'`**: The root `lib/utils.ts` exports `cn` using `clsx`+`tailwind-merge`. The installed `'cn'` package also provides `cn`. Button uses the package; shared components should use `@/lib/utils` for consistency.

8. **Dashboard route group structure**: Place pages at `app/(dashboard)/account/profile/page.tsx` NOT `app/(dashboard)/profile/page.tsx`. The `account` path segment is needed so URLs resolve as `/account/profile` (protected by middleware).

9. **`@react-pdf/renderer` in route handler**: `generateInvoicePDF` uses `renderToBuffer` which is Node.js-only. The API route will run in Node.js runtime (default) — ensure no `export const runtime = 'edge'` is added.

10. **Image optimization**: Use `next/image` for all product images. Supabase storage URLs need to be added to `next.config` `images.remotePatterns`. Create/check `next.config.ts` exists — if not, create it with the Supabase URL pattern.
